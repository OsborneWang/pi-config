argument-hint: "[commit-message]"

请执行 pmCloud 代码推送流程。

提交信息参数：${@:-未提供；由 agent 根据实际 diff 自行总结}

要求：
- 这不是默认动作，只有本命令触发时才执行。
- pmCloud 当前工作区包含三个独立 Git 仓库：`pmCloud_frontend/`、`pmCloud_backend/`、`pmCloud_specs/`；不要把根目录当成 Git 仓库。
- 无论当前对话历史是否有工作内容，命令不带参数时都扫描这三个仓库，并把每个仓库中已有的堆积变更分别提交并推送；没有变更的仓库跳过。
- 命令带参数时，不要把参数当成仓库、路径或范围；把 `/push` 后面的完整内容原样作为本次提交信息，例如 `fix:17436 【新】流程审核节点要通过微信公众号给指定人员发推送消息`。
- 命令带参数时，仍然扫描三个仓库并分别推送有变更的仓库；同一条提交信息可用于所有存在变更的仓库，除非 diff 显示多个不相关主题必须拆分。
- 命令不带参数时，由 agent 根据每个仓库的实际 diff 自行总结简洁提交信息；不同仓库可以使用不同提交信息。
- 如果当前对话历史能明确区分“本次工作”和“无关堆积变更”，优先只提交本次工作相关变更；但当命令不带参数且用户明确要求推送三个仓库时，默认处理三个仓库内全部堆积变更。
- 在提交前执行 `git status` 和必要的 diff 检查，确认没有调试残留、敏感信息、明显临时文件或不应推送的产物。
- 如果发现未完成实现、测试失败、冲突、未解决 TODO、敏感信息、错误仓库、多个候选范围无法判断，先停下报告，不要提交或推送。
- 如果存在多个独立仓库需要推送，分别处理每个仓库，分别生成提交并推送到各自当前分支的远程 upstream。
- 不要使用 `git push --force` 或破坏性 git 命令，除非用户明确要求。
- 如果当前分支没有 upstream，先报告拟推送的 remote 和 branch；只有在 remote/branch 明确且无歧义时才设置 upstream 并推送。
- 提交信息要简洁描述实际业务变更；命令带参数时优先使用用户提供的完整提交信息，不要擅自改写。只有在仓库 diff 明显与该提交信息无关时，先停下报告。
- 推送成功后，给出简短汇报：仓库、分支、提交 hash、推送目标、验证或未验证项。
